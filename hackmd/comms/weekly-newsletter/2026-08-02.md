## Weekly Newsletter (ElizaOS) — 2026-07-27 to 2026-08-02

### 1) Executive Summary

This week was a strong blend of **ecosystem expansion** and **framework hardening**:

1. **`eliza.army` launched (in-repo) with a contribution skill + public leaderboard**  
   The community now has a concrete on-ramp for “reviewable agent compute” contributions: a downloadable skill that can pick up work safely (claims, evidence, tests, model disclosure), plus a Vite site that surfaces a transparent leaderboard and workflow rules. This merged to `develop` as **PR #17424**.

2. **Reliability wins across core + Cloud safety boundaries**  
   Several fixes landed that reduce “silent wrongness” and production risk: provider deadline behavior is now cancellation-safe, Cloud snapshot retention is bounded by what restore can actually consume, and lifecycle reads now type date fields correctly (real `Date`s rather than raw DB strings).

3. **Community shipped two new “agent-adjacent” tools to test and stress**  
   Discord saw the launch of **Coopa v4.0** (client-side encrypted “digital sanctuary” on Sepolia + Irys/Arweave) and a new **Solana pre-trade verification plugin** from PnL Labs aimed at safer on-chain execution for agents.

### 2) Development Updates (Technical)

**Major feature merged**
- **`feat: launch eliza.army contribution skill and leaderboard` (merged)** — [elizaos/eliza#17424](https://github.com/elizaos/eliza/pull/17424)  
  Highlights:
  - Bundled **`contribute-to-eliza`** skill: enforces claim discipline, scoped validation, evidence attachment, and model attribution.
  - New package: **`packages/eliza-computer`** (Vite site) with a GitHub snapshot, work queue, and leaderboard rendering.
  - CI/CD: Cloudflare Pages deployment flow with byte-level verification via manifests (deploy remains protected until merge + env approval).
  - Repo-wide contribution policy tightening: templates + checks for evidence and attribution.

**Core runtime correctness / “fail less weirdly”**
- **Provider deadlines now cancellation-safe** — [#17490](https://github.com/elizaos/eliza/pull/17490)  
  Fixes a subtle failure mode where providers could be raced without proper abort semantics, leading to incorrect cached timeouts and degraded context quality.

- **Stage-1 always renders `CURRENT_TIME` (removes regex intent gate)** — [#17500](https://github.com/elizaos/eliza/pull/17500)  
  Addresses a real incident where the system answered the wrong date/time despite having a prompt contract to provide current time reliably.

- **Tool failures now “answer honestly” instead of falling back to generic apologies** — [#17501](https://github.com/elizaos/eliza/pull/17501)  
  Important for operator trust: when a tool fails, the response should reflect the actual failure instead of masking it with a generic planner fallback.

**Cloud safety and lifecycle integrity**
- **Bound v1 snapshot retain budget by restore consumption** — [#17180](https://github.com/elizaos/eliza/pull/17180)  
  Reduces the risk of snapshot accumulation exceeding what restore workflows can safely handle.

- **Type lifecycle reads so date fields become real `Date` objects** — [#17262](https://github.com/elizaos/eliza/pull/17262)  
  Eliminates a class of lifecycle mutation bugs caused by raw row typing (string timestamps leaking into logic).

**UI + testing hygiene**
- **Notification collapse fade symmetry fix** — [#17518](https://github.com/elizaos/eliza/pull/17518)  
  Small UI details, but they matter—especially when paired with device-specific regressions reported below.

- **Test harness determinism improvements** — [#17513](https://github.com/elizaos/eliza/pull/17513)  
  Isolates agent memory + voice harness state so suites run cleanly together and independently (less “order-dependent red CI”).

**Important open items worth tracking**
- **LP3 (Light Phone 3) home surface regression** — [issue #17502](https://github.com/elizaos/eliza/issues/17502)  
  Reports a serious small-viewport regression (notifications clamped to 40% height; launcher row becomes zero-area). This is a prime target for quick community reproduction + CSS/layout fix validation.

- **CI gap: plugin unit tests not required pre-merge on `develop`** — [issue #17550](https://github.com/elizaos/eliza/issues/17550)  
  This is a “timing hole” (tests run post-merge), which can let breakage land and slow everyone down.

- **Cloud runtime provider ownership edge case** — [issue #17516](https://github.com/elizaos/eliza/issues/17516)  
  A nuanced but high-impact boundary: Cloud-managed capabilities vs direct provider routing (OpenAI/Ollama/Cerebras/local) should preserve owner intent.

### 3) Community Spotlight (Discord)

**Coopa v4.0: privacy-first “digital sanctuary” stress test call**  
Selcuk / `nativesatoshi` shared **Coopa v4.0**, deployed on **Sepolia**, where files/messages are **encrypted client-side** before being stored on **Irys/Arweave**—meaning servers never see plaintext. Power users are invited to **stress-test the architecture** and provide UX feedback.  
Links shared:
- Live app: https://coopaassistant.com  
- Sepolia faucet: https://sepoliafaucet.com  
(Discord: [#💬-discussion](https://discord.com/channels/1253563208833433701/1253563209462448241))

**PnL Labs shipped a Solana “pre-transaction verification” plugin**  
`pnllabs_13084` announced **`@pnllabs/plugin-pnllabs`**: wallet trust scoring (based on realized on-chain PnL), token safety checks, real trade cost analysis, and funding forensics. A notable finding: after auditing 30 “smart money” wallets, **~50% were actually losing money**—a good reminder that agent routing should be skeptical by default.  
Distribution: npm, with a free tier (no API key), pay-per-call beyond that via **x402**.

**Safety note: scam account warnings**  
Two users flagged suspected scam accounts in discussion. As always: verify identities, avoid unsolicited DMs, and sanity-check “too good to be true” offers.

**Unanswered but important question**  
A community member asked how to **bridge funds from Base to Solana** and didn’t get an answer this week. If you have a vetted flow (canonical bridge + risk notes), consider replying next week—this is exactly the kind of practical knowledge that helps new builders ship.

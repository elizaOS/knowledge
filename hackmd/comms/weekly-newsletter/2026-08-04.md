# ElizaOS Weekly Newsletter (2026-07-28 → 2026-08-03)

## 1) Executive Summary

**1) `eliza.army` shipped (and it’s a big deal).**  
This week saw the merge of **“feat: launch eliza.army contribution skill and leaderboard”** ([PR #17424](https://github.com/elizaOS/eliza/pull/17424)). It introduces a new public-facing contribution flow: a downloadable skill for issue/PR work (with claims, validation, and model disclosure) plus a Vite-powered site that surfaces a work queue and leaderboard. It also formalizes evidence and attribution expectations across the repo.

**2) Reliability wins across CI + runtime behavior.**  
Multiple merges focused on making development and releases more predictable: protecting self-hosted runners from destructive pruning ([PR #17535](https://github.com/elizaOS/eliza/pull/17535)), strengthening develop PR gates to catch plugin test regressions pre-merge ([PR #17552](https://github.com/elizaOS/eliza/pull/17552)), and hardening how the agent answers when tools fail so it doesn’t hide behind generic fallbacks ([PR #17501](https://github.com/elizaOS/eliza/pull/17501)).

**3) Community momentum is real—but communication gaps are showing.**  
Discord conversations highlighted both optimism (partners noticing increased repo activity) and frustration (concerns about abandonment, missing “start here” docs links, and unfulfilled token utility expectations). The good news: there’s clear appetite to contribute—if we make onboarding and roadmaps easier to find.

## 2) Development Updates (Technical Highlights)

### Contribution + governance infrastructure
- **`eliza.army` contribution skill + leaderboard launched** ([PR #17424](https://github.com/elizaOS/eliza/pull/17424))  
  Adds a structured workflow for agent-assisted contributions, including evidence bundling, anti-fabrication checks, and model attribution. Also introduces Cloudflare Pages deployment plumbing (protected environment approval) and a transparent GitHub-backed leaderboard snapshot.

### CI hardening & developer experience
- **Runner workspace pruning fixed safely** ([PR #17535](https://github.com/elizaOS/eliza/pull/17535))  
  Self-hosted runner “pruners” now protect GitHub Actions control directories (like `_temp`, `_tool`, etc.), preventing flaky failures caused by deleting runner-owned paths mid-job.
- **Develop PR gate now runs plugin unit tests when relevant** ([PR #17552](https://github.com/elizaOS/eliza/pull/17552))  
  This closes a painful timing hole where plugin tests only ran *after* merge. Now, changed plugin packages can be required checks before landing on `develop`.
- **More deterministic smoke/audit classification** ([PR #17553](https://github.com/elizaOS/eliza/pull/17553))  
  Adds test coverage around “LifeOps activity-signals” smoke classification so expected 503s don’t masquerade as flaky failures.

### Agent/runtime correctness and user-facing integrity
- **Tool failures now “answer honestly”** ([PR #17501](https://github.com/elizaOS/eliza/pull/17501))  
  Instead of routing tool errors into generic apologies, the system surfaces the real failure boundary and preserves useful responses where possible.
- **Time rendering fixed at Stage-1** ([PR #17500](https://github.com/elizaOS/eliza/pull/17500))  
  Removes a fragile “prose-regex intent gate” so `CURRENT_TIME` is always rendered, avoiding incorrect date/time answers.
- **Prompt cache reuse improved** ([PR #17515](https://github.com/elizaOS/eliza/pull/17515))  
  Reorders volatile prompt parts to increase cache hits (notably for providers that cache prefix blocks), improving latency and cost efficiency.

### Notable open work worth tracking
- **Massive repo cleanup / CI hardening refactor** ([PR #17585](https://github.com/elizaOS/eliza/pull/17585))  
  Huge net deletions suggest a major directional consolidation. Watch this one closely—high impact, high risk, potentially very positive.
- **i18n catalog repair + CI wiring proposed** ([PR #17606](https://github.com/elizaOS/eliza/pull/17606))  
  Restores hundreds of missing English source keys and wires a previously-uninvoked checker into CI, making translation debt visible instead of silent.
- **Fork PR gates timing out on `action_required`** ([Issue #17551](https://github.com/elizaOS/eliza/issues/17551))  
  A real contributor-experience issue: aggregate gates poll for checks that can’t start until a maintainer approves workflows, producing red checks and burning runner time.

## 3) Strategic Prioritization (Impact / Risk / Dependencies)

### Priority queue (next 7–14 days)

#### A) Stabilize Cloud provisioning (P0: retention + revenue protection)
**Why now:** 16% failure is catastrophic at scale; 52-minute failure notification is unacceptable UX; also creates permanent lockout per issue narrative.  
**Key suspected causes (from #18052):**
- Fleet capacity saturation + placement funneling
- Autoscaler scale-up gate hardcoded ceiling (**12**) while **14 enabled** → can only drain
- Replacement-cleanup fence deadlock causing 409 enqueue refusals  
**Dependencies:** cloud ops + autoscaler config + provisioning worker deploy cadence (note daemon pinned behind mainline fixes).

**Recommendation**
- Allocate a **strike team (1 infra + 1 cloud backend + 1 oncall PM)** to:
  1) Ship autoscaler ceiling/env override + reconcile enabled node count logic.
  2) Add immediate operator-visible metrics: failure rate, enqueue 409s, fence count over time, free slots.
  3) Reduce failure-path user notification from ~52 minutes to <5 minutes via early terminal state + surfaced reason.

#### B) Fix login interactivity gating (P0/P1: top-of-funnel conversion)
**Problem:** `/steward/auth/providers` is 10× slower than neighboring route warm; spikes to multi-seconds; blocks sign-in CTA render (issue #18049).  
**Recommendation**
- Treat providers list as **cacheable configuration**; implement edge caching with explicit invalidation strategy.
- Add synthetic monitoring (p95 latency + cold-start budget) and alerting for this endpoint specifically.

#### C) Restore staging fidelity & prevent false-green signals (P1: regression prevention)
**Problem:** “staging lane silently tests prod” risk (issue **#18076**).  
**Recommendation**
- Separate “prod” and “staging” E2E jobs with:
  - explicit base URL assertions
  - staging-scoped credentials
  - artifacts labeled by environment
- This is a **force multiplier**: reduces late regressions and production-only surprises.

#### D) Community trust repair package (P1: narrative + support debt)
**Signals:** token migration missed window unresolved; governance confusion; competitive differentiation questioned; sentiment pessimistic (Discord 2026-08-13).  
**Recommendation**
- Publish a **pinned Discord post + website FAQ** covering:
  - token migration status/options (even if answer is “no on-chain path; here’s why”)
  - governance structure (who controls what, decision rights)
  - 2026 differentiation: concise product thesis tied to shipped capabilities (voice parity, workflow studio, reliability hardening)
- Assign a single accountable owner (community/ops) to **close loops** on these questions within 24–48h.

### Resource allocation (practical)
- **60%**: Cloud reliability (provisioning + auth/login + connector onboarding)
- **25%**: Test/staging integrity (prevent regressions, reduce firefighting load)
- **15%**: Community comms + documentation closure (reduce repeated support cost; improve sentiment)

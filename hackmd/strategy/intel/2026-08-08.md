## 3) Strategic Prioritization (impact vs risk, dependencies, resourcing)

### Initiative evaluation (next 2–6 weeks)

#### 1) Community reset: “tech-only” operating model (High impact, Low–Medium technical risk)
**Why now:** it directly protects development efficiency and contributor retention.

**Recommendation**
- Implement **hard moderation policy** immediately:
  - Ban **token price talk** in core channels; redirect to a quarantined channel or external forum.
  - Add **auto-moderation** (keyword rules, rate limits) + “ban agents” for repeat offenders.
- Create a **new onboarding funnel**:
  - “Start here: build” channel with pinned roadmap, “how to contribute”, and weekly demo schedule.
  - Separate “legacy token” FAQ/statement into a locked read-only channel to reduce repeated disputes.

**Success metrics**
- % messages in technical channels vs price/legal channels.
- # of unique contributors posting code/help per week (Discord → GitHub conversion).

#### 2) Consumer app MVP definition (Very high impact, Medium–High risk due to scope)
**Observation:** community suggested many verticals; scope must be constrained.

**Recommendation (MVP wedge)**
Pick **one primary wedge** + **one secondary** to validate the “agent OS” loop:

- **Primary wedge: Research assistant with local document write-back**
  - Rationale: clear demand, high daily frequency, measurable outcomes, strong differentiation if it edits *local* docs reliably.
  - Build: document connector + insertion/formatting + citations + change-tracking.
- **Secondary wedge: Personal assistant core (calendar + reminders + messaging)**
  - Rationale: aligns with OS vision and existing infra work (voice, scheduled task delivery correctness, onboarding/SSO).

Defer (for now): tax optimization agent (legal/compliance risk), construction schematic generator (high UX + liability complexity), health/biohacking peptide tracking (medical risk).

**Critical dependencies**
- Robust identity + onboarding: app-mode onboarding + SSO bridge must be stable.
- Voice parity: voice needs to behave like text channels (avoid filler/ack divergence).
- “Hidden Web3”: only after baseline trust UX exists; treat as capability gating.

#### 3) “Hidden Web3” payments as an optional capability (High impact, High trust risk)
**Recommendation**
- Implement as **progressive disclosure**:
  - Default: no wallet surfaces.
  - Enable payments only after explicit user opt-in + identity confirmation (“Danny” resolution).
- Add **transaction preview-first** requirement (no silent writes), mirroring the “preview-first” safety posture seen in plugin contributions.

**Success metrics**
- Payment attempt completion rate; reversal/support tickets; mis-send incidents (must be near-zero).

#### 4) Auditable computation traces (Medium impact now, High long-term trust leverage)
**Context:** DeFi O(1) formulas are fast, but production users/auditors want reproducibility.

**Recommendation**
- Define a **Trace Contract** for financial calculators:
  - Inputs normalized + hashable
  - Formula versioning
  - Step-by-step derivation output (machine-verifiable JSON), even if computation is O(1)
- This becomes reusable beyond DeFi (tax, budgeting, “why did you do that?” in agent OS).

### Resource allocation (pragmatic)
- **Allocate a named owner (even part-time) for community ops** for 2 weeks to implement moderation + restructure channels. This is the fastest way to restore developer throughput.
- **Keep current engineering bias toward reliability** (CI, security boundaries, voice latency), but explicitly timebox:
  - 60–70% reliability/ops until the consumer MVP is stable on a single host/app surface
  - 30–40% product wedge work (doc write-back + calendar/reminders loop)

### Immediate action list (next 72 hours)
1. Publish a **single canonical statement**: token status, governance, treasury, “what continues”, and where technical discussion happens.
2. Ship Discord changes: tech-only channels, quarantine token chatter, auto-mod rules.

4. For DeFi: answer/decide trace question and, if “yes”, draft a minimal **verifiable trace schema**.

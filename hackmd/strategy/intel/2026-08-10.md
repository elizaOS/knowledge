## 3) Strategic Prioritization (Impact × Risk, Dependencies, Resource Allocation)

### Priority stack (next 7–14 days)

#### P0 — Fix production provisioning regression (user creation path)
- Why now: measurable **16% failure**, and failure UX is catastrophic (**~52 min** + potential permanent lockout).
- Dependencies (per issue description):
  - Fleet capacity & placement constraints
  - Autoscaler maxNodes hardcode
  - Replacement-cleanup “fence” deadlock + 409 enqueue refusals
  - Production daemon pinned behind `main` (deployment lag risk)
- Recommendation:
  1) Assign 1–2 infra owners to ship a **production-pinned hotfix** (not just merged-to-main).
  2) Add an operational SLO: provisioning failure rate < **1%** rolling 7 days; failure notification < **2 minutes**.
  3) Add a user-facing “provisioning still in progress” path (don’t drop/lock out), plus an automatic remediation path for “error row blocks provisioning”.

#### P0 — Reduce login “time-to-first-action” by caching providers list
- Why: first impression; measured up to **4.7s** where page paints in ~92ms.
- Recommendation:
  - Cache `/steward/auth/providers` response with explicit TTL and safe invalidation strategy.
  - Add synthetic monitoring p95/p99 on this endpoint in prod and staging; target **p95 < 300ms**.

#### P1 — Make staging tests actually stage (prevent prod-default false greens)
- Why: release safety + trust; current “green” can be misleading.
- Recommendation:
  - Split “prod live” vs “staging live” E2E jobs with explicit base URLs + assertions on resolved host.
  - Require staging-scoped credentials for staging lane; fail closed if absent.
  - Add an artifact banner: “This run validated: PROD/STAGING”.

#### P1 — Token narrative containment (comms + moderation + safety)
- Goal: stop token governance ambiguity from consuming product channels and creating scam surface.
- Recommendation:
  - Pin a **Token Status & Safety** post:
    - What is officially supported (open-source software)
    - What is not (no token support/buybacks)
    - Who (if anyone) has authority; if unknown, explicitly say “unknown; do not trust DMs”
  - Add a single dedicated channel for legacy token discussion; enforce “no price talk” elsewhere if that’s the desired posture.
  - Add an automated scam warning banner + reporting workflow; publish “never share keys / never trust token recovery offers”.

#### P2 — Mobile distribution clarity (close the “App Store” confusion loop)
- Recommendation:
  - Add a “Mobile status” FAQ and a single canonical link (web app, TestFlight if any, or “not available”).
  - If “phone partnership” is real but not shippable soon: communicate timeline as “exploratory” to prevent expectation debt.

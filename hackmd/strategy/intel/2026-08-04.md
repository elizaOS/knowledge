## 3) Strategic Prioritization (Impact vs risk, dependencies, resource allocation)

### Priority stack (next 7–14 days)

**Initiative:** “Project Status & Roadmap Minimum Viable Transparency”
- Deliverables:
  - Weekly “Dev Pulse” post (Discord + GitHub Discussion): merged PRs, active epics, what’s next, who’s owning what.
  - Public response to “abandoned?” narrative with concrete artifacts (recent merges, active PRs, milestones).
- Dependency: none; requires maintainer time + comms owner.
- Expected effect: reduces churn, increases contributor conversion, lowers repeated questions.

#### P0 — Fix onboarding discoverability (low risk, immediate contributor yield)
**Initiative:** “Start Here: one link, everywhere”
- Deliverables:
  - Pin a canonical **Start Here** message in **#coders** and **#discussion**.
  - Add Discord bot auto-reply/FAQ command for: `!start`, `!docs`, `!contribute`.
  - Ensure eliza.army page links back to “Start Here” and vice versa.
- Dependency: confirm authoritative doc location; minor bot/config changes.
- Metric targets:
  - Reduce “where do I start?” questions by **>50%** week-over-week.
  - Increase first-time contributor PRs (proxy: new external PR authors) by **+10–20%** over baseline.

#### P1 — Token utility: convert ambiguity into an executable spec (medium risk, high trust impact)
**Initiative:** “Token Utility: Spec → Roadmap → Proof”
- Deliverables:
  - Publish a short spec: what token utility is (and isn’t), current state, planned milestones.
  - If utility is intentionally community-built, document “how to add utility” with technical pathways, examples, and security boundaries.
  - Open/label a tracking epic with acceptance criteria; link it in Discord FAQ.
- Dependency: product/lead decision on scope + legal/compliance review if applicable.
- Risk: overpromising again; mitigate by shipping only what is already resourced.

#### P1 — Manage large refactor risk (high technical risk, high blast radius)
**Initiative:** “PR #17585 risk gating”
- Deliverables:
  - Require staged review: diff segmentation, explicit deletion inventory, rollback plan.
  - Add CI checks for accidental removal of contributor onboarding assets/docs.
- Dependency: maintainer review bandwidth; CI configuration.

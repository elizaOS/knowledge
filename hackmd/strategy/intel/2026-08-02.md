## 2) User Experience Intelligence

#### A) Critical UX break (High impact, narrow device)
- **LP3 home/chat layout regression (#17502):**
  - Notifications region hard-capped (max-height 40%), launcher row becomes non-hittable (0x0 bounds).
  - Outcome: home surface functionally unusable on LP3; demo device rolled back.
  - Theme: **responsive layout policies not validated on short viewports**; missing guardrails in UI regression testing matrix.

**Opportunity:** add a “short-viewport” golden test profile (1080×1240 portrait) to existing Playwright/UI audit gates; treat layout constraints like `max-height:%` as risk flags requiring explicit device exceptions.

#### B) Reliability / correctness (High impact, broader)
- **Direct-provider ownership in Cloud runtime (#17516):**
  - Users intend hybrid routing (Cloud-managed capabilities + direct LLM/embeddings). Current plugin collector strips providers too aggressively; hydration early-return can preserve routes for providers never loaded.
  - Theme: **configuration intent not preserved**; “principle of least surprise” violated in routing.

**Opportunity:** formalize “routing intent invariants” in tests (route implies plugin ownership) and expose a runtime diagnostic (e.g., `effectiveRouting` vs `configuredRouting`) for supportability.

#### C) Support experience gaps (Medium impact, broad)
- **Unanswered questions:** bridging Base→Solana; opening a ticket.
- Theme: **no clear support intake path** inside Discord; questions fall through.

**Opportunity:** add a pinned “Support & Tickets” post + bot workflow (FAQ + escalation), and a lightweight “unanswered queue” triage rotation.

#### D) Trust & safety (Medium-high impact, broad)
- Scam warnings + accusations without clear moderator disposition.
- Theme: **community safety signaling incomplete** (users warn each other, but no authoritative action is visible).

**Opportunity:** standardize “scam report → mod acknowledgement → action taken” loop; publish a short checklist for verifying staff/official accounts.

## 3) Strategic Prioritization (Impact × Risk × Dependency)

### Priority 0 — Protect `develop` integrity (highest leverage)
**Initiative:** Make plugin unit tests required pre-merge to `develop` (#17550)  
- **User impact:** High (prevents breakages reaching users/devs)  
- **Technical risk:** Low–Medium (CI time increase, workflow tuning)  
- **Dependency:** None; unblocks smoother merges across teams  
- **Recommendation:**  
  1) Add PR-triggered plugin test job gated by path filters (`plugins/**`) to control wall-clock.  
  2) Make it **required** for `develop` merges.  
  3) Add a “deliberate break / restore” proof PR (as requested in acceptance criteria) to validate gate behavior.

**Resource ask:** 1 engineer, 0.5–1 day plus CI observation.

---

### Priority 1 — Fix LP3 regression (user-visible “broken home”)
**Initiative:** Resolve LP3 home surface layout regression (#17502)  
- **User impact:** High for LP3 target users; also reduces risk for other compact devices  
- **Technical risk:** Medium (CSS/layout changes can regress other viewports)  
- **Critical-path dependency:** Needs deterministic reproduction + targeted responsive rule changes; should be paired with new regression coverage.

**Recommendation (execution plan):**
1) Confirm culprit via quick bisect/revert test of suspected commit (`max-height: 40%` and launcher page assumption).  
2) Replace percentage cap with:
   - content-aware sizing (min/max in px tied to viewport height) or
   - LP3 media query override + keep launcher accessible (no 0-area hit targets).  
3) Add UI audit fixture for **1080×1240 portrait** and assert:
   - launcher buttons have non-zero bounds,
   - notifications region exceeds minimum usable height,
   - keyboard open does not reduce content to unusable scroll traps.

**Resource ask:** 1 UI engineer, 1–2 days including test coverage.

---

### Priority 2 — Cloud/direct provider routing correctness (hybrid users)
**Initiative:** Preserve direct provider ownership in Cloud runtime (#17516)  
- **User impact:** High for power users and production hybrid deployments  
- **Technical risk:** Medium–High (routing and plugin loading boundary; risk of subtle regressions)  
- **Dependency:** Needs clear invariants + policy tests across providers (Cerebras/Ollama/OpenAI/local)

**Recommendation:**
- Define and enforce invariants:
  - “If a route references provider X, provider X must be loaded” (and only required providers are loaded).
  - “Cloud-managed capabilities must not override explicit direct routes.”
- Add focused tests for canonical `serviceRouting` without deprecated `config.cloud` block to prevent early-return mis-hydration.
- Provide a non-secret “provider evidence” hook (sanitized) to show which provider served a request in logs (helps support without credential exposure).

**Resource ask:** 1 core/runtime engineer, 2–4 days.

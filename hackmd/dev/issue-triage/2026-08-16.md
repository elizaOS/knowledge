## Cross-Issue Patterns / Themes (Possible Deeper Architectural Signals)
- **Environment/host ambiguity (staging vs prod):** Multiple items show “defaults that silently hit production” or “staging flows repoint to prod,” indicating insufficient **environment pinning and assertion** at boundaries (CI, UI client defaults, onboarding links).
- **Onboarding as a multi-surface distributed system:** Messaging connector → web login → Cloud identity → agent provisioning is fragile. Failures often manifest as loops, long spinners, or repeated onboarding prompts, suggesting missing **end-to-end state machines** and **idempotent continuation contracts**.
- **Fleet capacity + control-plane drift:** Provisioning reliability depends on autoscaler ceilings, warm pool policy, fencing cleanup, and daemon version skew. This indicates the need for stronger **config-as-contract** and **deployment parity** between `main` and running production daemons.
- **“Green CI” that doesn’t prove the right thing:** #18076 shows a systemic risk: tests can pass while validating the wrong environment/artifact.

## Process Improvement Recommendations
1. **Fail-closed environment contracts everywhere:**
   - Add mandatory assertions in CI jobs and SDK clients for base URL / environment selection.
   - Emit “tested origin” metadata (artifact + logs) for every live lane.
2. **Promote production daemon parity checks:**
   - Add a release checklist item: “production provisioning daemon SHA matches release SHA (or documented pin).”
   - Alert when prod daemons lag behind `main` for critical systems (provisioning, gateway).
3. **Add E2E “first-contact” funnels as protected gates:**
   - Separate, minimal, fast (<60s) proofs for: login → identity link → provision/select agent → first reply for each connector (Telegram/Discord/Web).
4. **Shorten and surface failure paths:**
   - Replace multi-50-minute failure notification windows with fast-fail + actionable, typed errors (and UI messaging that guides recovery).
5. **Create a lightweight “Support/Policy” issue track:**
   - For non-code but brand-critical gaps (token migration FAQs, official channel lists), ensure there is a canonical GitHub issue and a documented owner.

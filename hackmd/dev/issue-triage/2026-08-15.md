2. **Onboarding identity binding is fragile across connectors**  
   - Telegram handoff demonstrates that “browser-authenticated” is being conflated with “connector-authenticated,” which is a security and correctness smell (#17888).
3. **Operational fixes not landing in the actually-running production daemons**  
   - Provisioning failure analysis highlights version skew and pinned services lagging `main` (#18052).
4. **Critical user journeys gated by single slow endpoints**  
   - Login buttons blocked on one providers endpoint (#18049), increasing churn risk.

## Process Improvement Recommendations (Prevention)

1. **Make environment targeting explicit and fail-closed**
   - Every live smoke/E2E job must assert its API origin and surface it in artifacts (no implicit defaults).
2. **Add “connector identity proof required” as a formal contract**
   - Codify a standard external-identity linking protocol (signed payload verification + freshness + replay protection) and reuse it across Telegram/Discord/SMS.
3. **Reduce production version skew**
   - Establish a “prod daemons must be within N commits / same tagged release” policy, with a dashboard check and an alert when drift exceeds threshold.
4. **SLO-driven onboarding observability**
   - Track: provisioning success rate, time-to-first-reply, login time-to-interactive, and connector-link completion rate; page on regressions rather than waiting for community reports.

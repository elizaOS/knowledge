## Patterns / themes indicating deeper issues
- **Routing/ownership boundaries are brittle**: #17516 suggests the Cloud/local/direct hybrid model has edge cases where plugin loading policy and persisted routes diverge. This is an architectural hotspot (boot-time arbitration + config hydration + plugin pruning).
- **“Quality failures are slipping left-to-right” via CI gaps**: #17550 shows timing holes where tests exist but don’t protect merges. This creates red `develop`, follow-up churn, and misattributed failures (“Windows failure” that is actually cross-platform).
- **Responsive UI assumptions aren’t guarded by representative viewport tests**: #17502 is a classic “works on tall phones” regression; device-class constraints (LP3 short panel) need explicit coverage.
- **Community trust requires operational muscle**: scam warnings with no visible resolution degrade confidence even if the code is solid.

## Process improvement recommendations
1. **Make “provider routing invariants” executable**: add a small suite of config-matrix tests that assert (a) persisted routes map to loaded providers and (b) Cloud vs direct ownership cannot be displaced unintentionally.
2. **Close CI timing holes with required checks**: ensure unit tests (including plugin tests) run on PRs to `develop` where merges happen; prefer changed-path scoping if runtime is a concern, but keep it required.
3. **Expand viewport regression coverage**: add a small set of “known constrained devices” (including 1080x1240 portrait) to UI visual gates so percentage clamps and off-surface elements get caught pre-merge.
4. **Codify Discord incident handling**: a short runbook (triage → containment → comms) plus pinned safety guidance and Automod baselines; ensure scam reports visibly conclude (action taken / no action + rationale).
5. **Weekly hygiene: “open-but-done” sweep**: automatically flag issues with merged closing PRs (e.g., #17510 vs #17513) to reduce backlog noise and improve signal-to-noise in triage.

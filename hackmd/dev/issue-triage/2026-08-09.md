# Process Improvement Recommendations

1. **Create a “Comms & Deprecation” playbook**: when a feature/project area is discontinued, require (a) a canonical statement, (b) link removals, (c) FAQ, (d) deprecation notice in repo/docs, (e) a final status page to reduce repeated questions.
2. **Add CI guardrails for fork approval semantics**: treat `action_required` as a first-class state in all aggregate gates; auto-comment on PRs explaining approval requirements rather than failing red after timeouts.
3. **Operationalize security PR landing**: for ingress/webhook/security PRs, require a short checklist: threat model summary, HITL plan owner, and a “release note stub” before merge.
4. **Closeout hygiene**: ensure issues that are closed by merged PRs are automatically reconciled (label/automation) so triage dashboards don’t show already-fixed items as “open.”

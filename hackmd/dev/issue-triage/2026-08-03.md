## Patterns / Themes Suggesting Deeper Issues
- **Lifecycle correctness remains a top systemic risk** (agent deletion, provisioning recovery, cloud runtime arbitration). Multiple recent fixes suggest the system is still converging on stable invariants.
- **CI signal quality vs contributor experience tension**: aggregate gates and required checks are powerful, but fork approval mechanics can invert their purpose (false reds + runner waste).
- **Policy/feature flags and “canonical config” migrations** are a recurring failure mode (early-return hydration, deprecated blocks, “canonical routing” assumptions).
- **High churn + large-scope PRs** increase regression probability; review bandwidth becomes a bottleneck and can delay P0/P1 stabilization.

## Process Improvement Recommendations
1. **Formalize P0 runbooks**: for production lifecycle incidents (like undeletable agents), require a minimal reproducible state capture template (tables/rows, lifecycle state machine position, job IDs).
2. **Fork PR “blocked-not-failed” CI standard**: required checks should never go red solely because maintainers haven’t approved runs; enforce a consistent “awaiting approval” outcome.
3. **Config migration guardrails**: when deprecating config blocks (e.g., `config.cloud`), add explicit tests that validate canonical paths and forbid silent early-returns.
4. **Large PR governance**: require “blast radius” summaries, rollback plans, and either (a) staged merges or (b) explicit maintainer sign-off before running repo-wide deletions/refactors.
5. **Community onboarding automation**: add a pinned canonical onboarding link + a lightweight bot/FAQ response for repeated questions (eliza.army, contribution workflow, evidence/model attribution).

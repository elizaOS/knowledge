# ElizaOS Developer Update (2026-08-10 → 2026-08-16)

This week concentrated on Cloud + onboarding hardening (SSO, connector identity binding, staging QA lanes), workflow studio stabilization, and a large batch of reliability/security fixes across the core runtime, gateways, and provider integrations. Discord discussion volume was low and mostly non-technical; one recurring community ask was adding/clarifying Telegram community channels (Discord thread summary: 2026-08-14).

## 1) Core Framework

### Runtime safety + determinism improvements
- **Provider deadlines are now cancellation-safe**: fixed a race where timed-out providers could keep running and cache a “timeout as empty context,” corrupting later turns. This is a correctness fix for the runtime’s state composition layer and affects *all* providers participating in `composeState`.  
  PR: https://github.com/elizaos/eliza/pull/17490

- **Planner turn-scope is now mandatory on every tool call**: the `eliza_turn_scope` declaration is required (e.g. `more_work_pending`) so the evaluator can reliably determine whether a turn should terminate. This reduces “early done” misclassification on small/reasoning models.  
  PR: https://github.com/elizaos/eliza/pull/18247

- **External-content security envelope no longer leaks into chat/tool params**: `hardenIncomingUserMessage` previously wrapped external text in-place, which then got echoed by downstream actions (search, plugin manager, app control). The fix introduces safe unwrapping + outbound guards.  
  PR: https://github.com/elizaos/eliza/pull/17629

### Trajectory + persistence hardening
- **Trajectory persistence is now envelope-first** so prompt truncation cannot poison the stored row (fixes `TRAJECTORY_TERMINALIZATION_FAILED` class failures).  
  PR: https://github.com/elizaos/eliza/pull/18267

- **Snapshot streaming for large agent backups**: `/api/snapshot` can now stream JSON rather than building a single huge string in memory. This prevents OOMs for large sandboxes.  
  PR: https://github.com/elizaos/eliza/pull/19080 (and production promotion https://github.com/elizaos/eliza/pull/19082)

### Workflow studio (Smithers / smthrs) foundation
- **Native workflow studio integration and runtime upgrade (smthrs 0.34.x)**: consolidated workflow editor surface, stabilized effect dependency closure, and aligned runtime/tooling contracts used by `plugin-workflow` and orchestrator.  
  PRs:
  - https://github.com/elizaos/eliza/pull/19000
  - https://github.com/elizaos/eliza/pull/19420
  - Studio completion: https://github.com/elizaos/eliza/pull/19052

## 2) New Features

### App-mode onboarding on `app.elizacloud.ai` (dedicated agent landing)
Logging in on the app host now lands directly in your dedicated agent (automatic selection, resume, and error fallback), instead of rendering a marketing byte-identical build.
- PR: https://github.com/elizaos/eliza/pull/17752

**Developer impact:** if you run a custom Pages host, the UI now branches behavior by host mode; ensure your deployment sets the expected origin(s) and that any reverse proxy preserves host headers.

### Cross-origin SSO bridge (dashboard ↔ app)
A single login now bridges sessions across origins using **atomic single-use codes** stored in Postgres, with PKCE binding and fail-closed logout semantics.
- PR: https://github.com/elizaos/eliza/pull/17788

**Example: exchanging an SSO bridge code (conceptual)**
```ts
// Pseudocode illustrating the expected one-time exchange pattern.
// See the SSO bridge route implementation and tests in #17788.

const res = await fetch("https://api.elizacloud.ai/auth/sso-bridge/exchange", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    code,                 // one-time bridge code
    pkceVerifier,         // PKCE verifier for binding
    targetOrigin: "https://app.elizacloud.ai",
  }),
});

if (!res.ok) throw new Error(`SSO exchange failed: ${res.status}`);
const { stewardSessionToken } = await res.json();
// Persist via the Steward session client (see packages/shared/src/steward-session-client)
```

Docs (updated as part of staging QA + auth work):
- https://github.com/elizaos/eliza/pull/18223 (also touches `packages/docs/cloud/authentication.mdx`, `packages/docs/cloud/api/api-keys.mdx`)

### Staging-only QA session exchange (for real staging E2E)
Added a **disabled-by-default** staging-only API-key → Steward-session exchange route to enable browser-based staging QA without teaching the browser to accept API keys directly.
- PR: https://github.com/elizaos/eliza/pull/18223

### Fish Audio streaming TTS plugin
Introduced **streaming TTS** integration via `plugin-fish-audio`, including Cloud voice session wiring and tests.
- PR: https://github.com/elizaos/eliza/pull/17709

### Core: bounded PairingService reads (scale safety)
Pairing reads are now bounded/paginated to prevent unbounded memory pressure under large pairing tables; adapters (`inmemorydb`, `sql`) were updated accordingly.
- PR: https://github.com/elizaos/eliza/pull/18203

## 3) Bug Fixes (critical)

### Cloud onboarding + connector identity binding fixes
- **Telegram onboarding continuation is now secure and durable**: fixes the class where a Telegram DM → browser sign-in never binds Telegram identity, resulting in repeated onboarding replies forever. The fix carries an opaque continuation, verifies Telegram HMAC/freshness server-side, and links identities only after proof.  
  PR: https://github.com/elizaos/eliza/pull/18101  
  Related open issue (original symptom report): https://github.com/elizaos/eliza/issues/17888

- **Discord onboarding continuation now enforces signed Discord identity match**: prevents a browser-authenticated session from claiming an arbitrary Discord sender identity.  
  PR: https://github.com/elizaos/eliza/pull/19133  
  Issue: https://github.com/elizaos/eliza/issues/18058

- **Messaging users whose agent is still provisioning are no longer silently dropped** (gateway now replies with a provisioning-aware response rather than dropping).  
  PR: https://github.com/elizaos/eliza/pull/17746

### Cloud “cache warming” reliability (503s on cold Workers)
A lot of production-facing work addressed Cloudflare Worker cold-start 503s (`*_cache_warming`) across chat, embeddings, image describe/generate, and media generation:
- Retry in-place for chat warming: https://github.com/elizaos/eliza/pull/17875  
- Embeddings warming retry: https://github.com/elizaos/eliza/pull/18158  
- Image description + fail-closed handling: https://github.com/elizaos/eliza/pull/18323  
- Image generation warming retry: https://github.com/elizaos/eliza/pull/18325  
- Video/music warming retry: https://github.com/elizaos/eliza/pull/18333  
- Auth-cache warming now has a deadline + authoritative escape: https://github.com/elizaos/eliza/pull/18249

### Voice parity + real-time stability
- **Realtime STT transport recovery**: keeps calls alive across Cartesia Ink transport errors with bounded reconnect, buffering metered PCM.  
  PR: https://github.com/elizaos/eliza/pull/19548

- **Barge-in / voice cold-start improvements moved into production** (prewarm voice scope + conversation DO; interruptible greetings).  
  PR: https://github.com/elizaos/eliza/pull/19655

### Discord plugin correctness + startup/shutdown stability
- **DM lane is no longer broken by guild allowlists** (`CHANNEL_IDS` previously suppressed DMs).  
  PR: https://github.com/elizaos/eliza/pull/18419

- **Wait for ready identity before ingress** to avoid early `messageCreate` before async hydration completes.  
  PR: https://github.com/elizaos/eliza/pull/17645

### Core routing correctness: reduce over-routing + prevent double replies
- **Bare link shares route to web-read, not a coding-agent spawn**.  
  PR: https://github.com/elizaos/eliza/pull/18106

- **Read actions that already answered stop the model’s second reply** (calendar and cloud account read ops were causing double-messages).  
  PR: https://github.com/elizaos/eliza/pull/18119

## 4) API Changes

### Shared SSE event contract is now canonical end-to-end
The shared chat SSE contract now uses a single builder for `chunk`, `done`, and `error` frames; producers/normalizers/transports/clients were aligned.
- PR: https://github.com/elizaos/eliza/pull/18477

**Client-side note:** if you have custom SSE consumers, stop relying on legacy “named events” drift; replay tests were added for canonical degraded + normalizer frames:
- PR: https://github.com/elizaos/eliza/pull/18487

### New/changed Cloud auth surfaces
- `/steward/auth/providers` is now “thin-path” (no full app bootstrap), reducing time-to-interactive on login surfaces.
  - PR: https://github.com/elizaos/eliza/pull/18717
  - Issue: https://github.com/elizaos/eliza/issues/18049

- **Public payment-request projection tightened**: public reads now use an explicit allowlist type; `agentId` is removed from the public creation contract and callback routing is constrained to `(roomId, agentId)` ownership.
  - Allowlist projection: https://github.com/elizaos/eliza/pull/18535
  - Remove public agent attribution: https://github.com/elizaos/eliza/pull/18820
  - Callback room binding: https://github.com/elizaos/eliza/pull/18546

## 7) Breaking Changes / V1 → V2 Migration Warnings

### Stricter runtime + tool contracts (expect CI/test updates)
These changes can break custom plugins/agents that depended on permissive behavior:
- **Planner tool calls must declare `eliza_turn_scope`** (missing scope now fails contract expectations).  
  PR: https://github.com/elizaos/eliza/pull/18247

- **Security envelope behavior changed**: do not assume `message.content.text` retains the original raw external content wrapper; if your plugin expects the envelope string, update it to use the safe unwrap utilities / structured attachment APIs.  
  PR: https://github.com/elizaos/eliza/pull/17629

### Cloud “v1 snapshot” safety alignment (migration context)
Cloud backup retention behavior was changed to bound the v1 snapshot retain budget by what restore can consume; this is an intentional safety alignment and a step toward the broader v2 backup protocol work (explicitly out-of-scope in the PR).  
- PR: https://github.com/elizaos/eliza/pull/17180  
- Tracking issue: https://github.com/elizaos/eliza/issues/17172

### Eliza Cloud consolidation host changes (watch for hard-coded origins)
If you have integrations that still assume legacy origins, audit them:
- Consolidation: https://github.com/elizaos/eliza/pull/18996  
- Recent staging origin pinning + onboarding host contracts:
  - https://github.com/elizaos/eliza/pull/18186
  - https://github.com/elizaos/eliza/pull/18465

### Active operational breaking risks (open issues to track)

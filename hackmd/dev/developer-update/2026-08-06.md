# ElizaOS Developer Update — 2026-08-02 to 2026-08-08

This update summarizes core runtime/CI hardening, voice streaming improvements, security boundary work, and key plugin changes landed or in-flight in `elizaos/eliza` during the week.

## 1) Core Framework

### Runtime environment unification (Bun pin)
All workflows and packages were aligned to a single Bun runtime version (`1.3.14`) to eliminate “works on my machine” drift across CI lanes and contributor environments.

- Issue: https://github.com/elizaos/eliza/issues/17044  
- PRs: https://github.com/elizaos/eliza/pull/17653, https://github.com/elizaos/eliza/pull/17637, https://github.com/elizaos/eliza/pull/17650  

**Developer impact**
- CI now assumes Bun `1.3.14` semantics and lockfile behavior; if you run a different Bun version locally you may see lockfile churn or inconsistent test outcomes.

```bash
# recommended local baseline
bun --version   # expect 1.3.14
bun install --frozen-lockfile
bun run verify
```

### Provider execution budgets + cancellation safety
A set of core providers were updated so time budgets are cancellation-safe (avoid caching “timeout → empty context” and leaving work running in the background).

- PR: https://github.com/elizaos/eliza/pull/17490

**Why it matters**
- Providers that hydrate state (recent messages, long-term memory summaries, relationship/facts providers, etc.) are now less likely to poison subsequent turns with partial/empty cached results when a deadline is hit under load.

### Planner-loop reliability under reasoning models
The planner budget logic was hardened for “reasoning-first” models that can burn completion tokens before emitting a required tool call. The fix widens the stream-start retry and prevents premature exhaustion when `toolChoice: required`.

- PR: https://github.com/elizaos/eliza/pull/17630

## 3) Bug Fixes (with technical context)

### Security: prevent untrusted content from polluting the “security envelope”
A critical class of “envelope echo” bugs was fixed: external `content.text` was previously wrapped in-place, and downstream actions/tools that used `message.content.text` could inadvertently ingest or leak the envelope markers.

- PR: https://github.com/elizaos/eliza/pull/17629

**Why it’s critical**
- This is a classic trust-boundary failure: untrusted wrappers can end up being interpreted as user input, tool arguments, resource names, or search queries, leading to confusing behavior or potential injection surfaces.
- The fix ensures external envelope markers do not get echoed back into tool calls or chat outputs.

### Cloud A2A boundary: reject caller-authored `system` policy
The public agent-to-agent boundary now rejects caller-authored `system` messages. Only ordinary conversation roles are accepted, and the rejection happens before billing/provider dispatch.

- PR: https://github.com/elizaos/eliza/pull/17643

**Developer impact**
- If you have an A2A client that injected `system` messages into the request payload, those calls will now fail fast.

### Discord connector: readiness race on gateway start
Discord could emit `messageCreate` immediately after `ClientReady` while `onReady` was still hydrating identity/aliases, causing incorrect routing/ownership decisions. The connector now waits for readiness identity before accepting ingress.

- PR: https://github.com/elizaos/eliza/pull/17645  
- Follow-up secret-scan false positive fix: https://github.com/elizaos/eliza/pull/17671  

### Skills tooling: GitHub CLI pagination compatibility (Ubuntu 24.04 baseline)
The contributor skill’s inventory step no longer depends on `gh api --slurp` (unsupported on GitHub CLI 2.45.0 shipped in Ubuntu 24.04). Pagination was rewritten to a compatible mechanism with deterministic tests.

- Issue: https://github.com/elizaos/eliza/issues/17674  
- PR: https://github.com/elizaos/eliza/pull/17675  

### CI stability: protect runner directories + safe pruning
A sequence of CI fixes eliminated flaky failures and accidental runner workspace deletion:
- Protect runner control directories from pruning: https://github.com/elizaos/eliza/pull/17535  
- Stop pruning when runner state is indeterminate: https://github.com/elizaos/eliza/pull/17575  
- Restore/repair CI matrix invariants (multiple lanes): https://github.com/elizaos/eliza/pull/17615

## 4) API Changes

### A2A chat request validation tightened (system role disallowed)
As noted above, the A2A public boundary rejects caller-authored `system` messages.

- PR: https://github.com/elizaos/eliza/pull/17643

**Migration snippet (client-side)**
If you previously sent:
```json
{
  "messages": [
    { "role": "system", "content": "You are agent A. Enforce policy X." },
    { "role": "user", "content": "Do the thing." }
  ]
}
```

Update to server-owned system policy (configured on the agent) and send only:
```json
{
  "messages": [
    { "role": "user", "content": "Do the thing." }
  ]
}
```

### Plugin test gating in CI for changed plugin packages
Develop PR gating now requires changed plugin packages to run their own unit tests (prevents “green root” while a plugin regresses).

- PR: https://github.com/elizaos/eliza/pull/17552

# ElizaOS Developer Update (2026-08-02 → 2026-08-08)

This week was primarily about **runtime + CI hardening**, **voice streaming parity**, and **Cloud reliability/security boundaries**, capped by a **develop → main production promotion**. Community discussion also clarified the near-term product direction: a **consumer-grade “assistant OS”** (notes/calendar/browser/messaging/wallet/social) with **optional Web3 infra hidden behind normal UX**.

### Agent boot + lifecycle ownership & shutdown correctness
Several runtime paths were updated to ensure **owner-controlled boot/benchmark** behavior and safe shutdown (avoiding “race + exit” patterns that could corrupt state):
- **fix(agent): benchmark and boot owner-controlled** (**#17531**)  
  https://github.com/elizaos/eliza/pull/17531

### Hardening inbound security envelopes (core)
We fixed a class of bugs where **the untrusted external-content envelope could leak back into normal chat/tool inputs**, polluting downstream tool calls and action routing:
- **fix: never echo the external-content security envelope into chat** (**#17629**)  
  https://github.com/elizaos/eliza/pull/17629

### Provider deadline handling is cancellation-safe
Provider budgets now abort cleanly instead of racing and caching timeouts as “empty context,” avoiding subtle state-provider corruption and long-tail latency:
- **fix(core): make provider deadlines cancellation-safe** (**#17490**)  
  https://github.com/elizaos/eliza/pull/17490

## 2) New Features (Detailed)

### Fish Audio streaming TTS (realtime voice)
We added **Fish Audio streaming text-to-speech** as a first-class voice provider integration, focused on **low-latency streaming turns** and Cloud voice session wiring:
- **feat: add Fish Audio streaming TTS** (**#17709**)  
  https://github.com/elizaos/eliza/pull/17709

In Cloud voice sessions, this lands as a provider-backed streaming implementation (server-side) plus a plugin package:
- Plugin package: `plugins/plugin-fish-audio`
- Cloud worker wiring: `packages/cloud/api/v1/voice/session/*`

**Minimal configuration sketch (server/worker env):**
```bash
# Cloud / Worker env
FISH_AUDIO_API_KEY="..."
# Optional provider tuning depends on deployment; see plugin README once published.
```

**Plugin registration sketch (agent runtime):**
```ts
import { fishAudioPlugin } from "@elizaos/plugin-fish-audio";

export const runtime = await createElizaRuntime({
  plugins: [
    fishAudioPlugin({
      apiKey: process.env.FISH_AUDIO_API_KEY!,
      streaming: true,
    }),
  ],
});
```

To reduce “first turn after idle” voice failures, we also warmed every cold cache that realtime voice reads:
- **fix(voice): warm every cold cache a realtime turn reads** (**#17744**)  
  https://github.com/elizaos/eliza/pull/17744

And we fixed a parity gap so private voice behaves like DMs/API for response grammar:
- **fix(core): align private voice with direct responses** (**#17863**)  
  https://github.com/elizaos/eliza/pull/17863

## 3) Bug Fixes (Critical, with context)

### Production Cloud inference “every other request fails” (billing/auth warm alternation)
A critical production issue caused ~50% of inference requests to fail with “Billing authorization is warming up,” alternating success/failure under otherwise healthy model latency. The fix republishes org-balance gate hints after debits to prevent thrash:
- **fix(cloud): republish org-balance gate hint after an inference debit** (**#17745**)  
  https://github.com/elizaos/eliza/pull/17745
- Shipped to production via promotion: **release develop → main** (**#17865**)  
  https://github.com/elizaos/eliza/pull/17865

### Calendar webhook ingress hardened (capability-bound + authz-before-DB)
Google Calendar push callbacks were refactored into a single security boundary with:
- default-off route registration
- destination-bound HMAC capability (`gcalwh.v1`)
- authz before any DB/service resolution
- replay suppression + exactly-once receipt/enqueue semantics
- key rotation + emergency revocation
- **fix(calendar): harden Google webhook ingress** (**#17649**)  
  https://github.com/elizaos/eliza/pull/17649

If you operate the calendar plugin, note the explicit HITL requirement: live Google callback evidence is still needed before claiming full production validation (documented in the PR).

### A2A trust boundary: reject caller-authored system policy
We closed a major injection vector by rejecting `system` messages at the public per-agent A2A boundary (fail before credit reservation/provider dispatch):
- **fix(cloud): reject caller-authored A2A system policy** (**#17643**)  
  https://github.com/elizaos/eliza/pull/17643

### Planner/tool-call budget starvation on reasoning models
Reasoning models could burn the entire completion budget “thinking” and never emit required tool calls. We widened retry behavior and fixed planner loop budgeting:
- **fix: chat planner budget starves required tool calls on reasoning models** (**#17630**)  
  https://github.com/elizaos/eliza/pull/17630

### Voice: interrupted turns persisted on the canonical DO path
Earlier work fixed the wrong path (legacy bridge). This week corrected the live realtime voice path so interrupted turns persist reliably:
- **fix(voice): persist interrupted turns on the canonical Durable Object path** (**#17644**)  
  https://github.com/elizaos/eliza/pull/17644

### Discord connector readiness race
Discord can emit `messageCreate` immediately after gateway ready while async hydration is still running. We now wait for ready identity before ingest:
- **fix(discord): wait for ready identity before ingress** (**#17645**)  
  https://github.com/elizaos/eliza/pull/17645
- Follow-up: avoid readiness diagnostic secret false positive (**#17671**)  
  https://github.com/elizaos/eliza/pull/17671

### CI reliability & contributor UX
Key CI fixes reduced wasted runner time and improved determinism:
- Protect runner control dirs from pruning (**#17535**)  
  https://github.com/elizaos/eliza/pull/17535
- Stop pruning runners whose state can’t be determined (**#17575**)  
  https://github.com/elizaos/eliza/pull/17575
- Develop test matrix restoration (**#17615**)  
  https://github.com/elizaos/eliza/pull/17615
- Fork gate polling issue remains tracked (action_required timeouts): **#17551**  
  https://github.com/elizaos/eliza/issues/17551

## 4) API Changes (Developer-visible)

### Cloud / internal routing changes
- `app-core` internal broker routes are now mounted under `/api/internal` so the dispatcher can reach them:
  - **fix(app-core): mount account-pool broker routes under /api/internal** (**#17782**)  
    https://github.com/elizaos/eliza/pull/17782

**Impact:** if you were hitting older internal paths directly (especially in bespoke deployments), update to the `/api/internal/*` mount convention.

### A2A boundary restrictions
- A2A public chat APIs now **reject caller-authored `system` messages**:
  - **#17643** https://github.com/elizaos/eliza/pull/17643

**Impact:** if you had custom A2A clients injecting `system` messages, migrate to:
- `user` messages (with explicit tool schemas where needed), or
- server-side policy configuration, not caller-provided system policy.

### SSO bridge endpoints (cross-origin auth)
SSO adds/changes auth routes in Cloud API (bridge + exchange + logout semantics):
- **#17788** https://github.com/elizaos/eliza/pull/17788

**Impact:** frontends should not write reserved auth storage keys directly; route via the shell channel (see **#17826**).

## 7) Breaking Changes / V1 → V2 Migration Warnings

### Bun runtime pin is now a contract
If your local/dev/CI environment assumes Bun canary or a different Bun minor, expect breakage. Align to the repository baseline:
```bash
bun --version  # should be 1.3.14
```
Relevant PRs include **#17653** (Windows gate), plus the broader unification tracked under **#17044**:
- https://github.com/elizaos/eliza/issues/17044  
- https://github.com/elizaos/eliza/pull/17653

### Cloud backup/snapshot safety alignment (v1 retention budget)
Cloud snapshot retention is now bounded by what restore can actually consume (immediate v1 safety alignment). This is not the full v2 backup protocol, but it changes operational expectations for snapshot lifecycle:
- **fix(cloud): bound the v1 snapshot retain budget by what restore can consume** (**#17180**)  
  (listed in completed items; see weekly summary)

**Migration note:** if you relied on unbounded snapshot retention (even unintentionally), audit your restore flows and retention assumptions.

### A2A “system message” injection is now blocked
Clients that used to send policy via `system` messages must migrate (see API Changes). This is intentionally breaking to enforce trust boundaries:
- **#17643** https://github.com/elizaos/eliza/pull/17643

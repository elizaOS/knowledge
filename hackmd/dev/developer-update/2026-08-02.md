## 1) Core Framework

### Provider execution: deadlines are now cancellation-safe
A critical correctness fix landed to ensure provider calls respect cancellation and do not “poison” subsequent context when a timeout occurs.

- **Fix:** `fix(core): make provider deadlines cancellation-safe` ([#17490](https://github.com/elizaos/eliza/pull/17490))
- **Context:** the prior implementation effectively imposed an implicit short deadline on providers, raced without aborting upstream work, and could cache a timeout as empty context. This created hard-to-debug “missing memory/context” regressions after transient timeouts.
- **Impact:** improved determinism for state composition and inference timing across providers like recent/relevant conversations and advanced memory providers.

### Cloud snapshot safety: retention bounded by restore consumption
Cloud agent backup/snapshot retention is now constrained by what restore can actually consume, preventing runaway retention and aligning v1 safety with restore limits.

- **Fix:** `fix(cloud): bound the v1 snapshot retain budget by what restore can consume` ([#17180](https://github.com/elizaos/eliza/pull/17180)) — implements **#17172 §1** only
- **Impact:** avoids silent accumulation of snapshots that cannot be restored within defined budgets; adds/updates verifier + diff tests around backup limits.

### Cloud lifecycle reads: timestamp fields are now typed as `Date`
A class of Cloud lifecycle mutation issues was addressed by typing lifecycle reads so date fields are real `Date` objects instead of raw DB row values.

- **Fix:** `fix(cloud): type the lifecycle read so date fields are real Dates` ([#17262](https://github.com/elizaos/eliza/pull/17262))
- **Impact:** reduces lock/retry edge cases and “stuck provisioning” behaviors caused by string timestamp comparisons and inconsistent serialization.

### Test harness determinism improvements
Two test harnesses were made deterministic and non-leaky across suites.

- **Tests:** `test: isolate agent memory and app-core voice harnesses` ([#17513](https://github.com/elizaos/eliza/pull/17513), tracks [#17510](https://github.com/elizaos/eliza/issues/17510))
  - Migrates a suite to the canonical Vitest runner.
  - Resets module registries after voice latency route tests to prevent mock leakage.

## 3) Bug Fixes (Critical/Notable)

### Time correctness: Stage-1 now always renders `CURRENT_TIME`
A real production incident was addressed where the system returned the wrong date/time despite the system prompt promising time awareness.

- **Fix:** `fix(core): Stage-1 always renders CURRENT_TIME — delete the prose-regex intent gate` ([#17500](https://github.com/elizaos/eliza/pull/17500))
- **Root cause:** an intent gate (regex/prose heuristic) prevented time injection in some queries.
- **Impact:** time-dependent behaviors (scheduling, “what time is it”, freshness checks) should now be consistently correct at Stage-1.

### Tool failure honesty: prevent generic fallback from masking real failure modes
- **Fix:** `fix: tool failures answer honestly instead of feeding the generic fallback` ([#17501](https://github.com/elizaos/eliza/pull/17501))
- **Impact:** reduces misleading assistant responses when a tool action fails (especially important for admin/control actions), and improves debuggability in logs and user-visible output.

## 4) API Changes

### Cloud/mobile auth foundations (server + iOS) remain in-flight (not merged)
Two large PRs define a **disabled-by-default** Authorization Code + PKCE lifecycle and an iOS native auth foundation. They regenerate routers and SDK wrappers, but are not merged this week (so treat as upcoming API surface).

- **Server (disabled by flags):** `feat(cloud): add disabled mobile PKCE auth lifecycle` ([#16641](https://github.com/elizaos/eliza/pull/16641))
  - Adds mobile-only credential rules (header-only; rejects query-string transport in websocket contexts).
  - Adds exchange/ack/revoke flows, cleanup, and additive DB migrations.
  - Regenerates the canonical Hono router + public SDK wrappers.
- **iOS foundation:** `feat(ios): add Cloud-only native authentication foundation` ([#16640](https://github.com/elizaos/eliza/pull/16640))
  - Raises iOS targets/Podfile to iOS 17.4 and introduces `ASWebAuthenticationSession` bridge.
  - Shifts App Store defaults to Cloud-only while retaining explicit local/remote developer lanes.

**Developer note:** if you maintain downstream tooling around the Cloud SDK surface area, watch these PRs closely; they imply new endpoints/types and stricter credential transport rules once enabled.

### Cloud runtime provider ownership (open issue; important for hybrid routing)
A newly filed issue highlights a Cloud-mode runtime bug where plugin collection may strip direct providers even when `serviceRouting` specifies an owner-routed provider (OpenAI, Ollama, Cerebras via OpenAI-compat mapping, local inference).

- **Issue:** `fix(agent): preserve direct provider ownership in cloud runtime` ([#17516](https://github.com/elizaos/eliza/issues/17516))
- **Why it matters:** hybrid deployments (Cloud-managed capabilities + direct LLM/embeddings routing) can silently load the wrong provider set or allow Cloud inference to displace the owner’s direct route.

## 7) Breaking Changes / Migration Warnings (V1 → V2 + contributor workflow)

### Contribution workflow + CI policy tightening may break existing contributor automation
The eliza.army launch PR ([#17424](https://github.com/elizaos/eliza/pull/17424)) updated:
- PR/issue templates
- Evidence + attribution enforcement
- Workflow expectations for model disclosure and durable attribution markers

If you have automation that opens PRs/issues/comments, ensure it emits the required attribution metadata and evidence links where applicable. Review:
- [`CONTRIBUTING.md`](https://github.com/elizaos/eliza/blob/develop/CONTRIBUTING.md)
- `.github/pull_request_template.md` (updated in [#17424](https://github.com/elizaos/eliza/pull/17424))

### Cloud snapshots: v1 retention behavior changed (safety alignment)
While not a “break” in API signature, Cloud snapshot retention behavior now enforces restore-consumption budgets ([#17180](https://github.com/elizaos/eliza/pull/17180)). If you relied on looser retention for out-of-band recovery workflows, validate that your restore procedures still meet the new constraints.

### Mobile auth changes are additive but will enforce stricter token transport once enabled
The mobile PKCE lifecycle PR ([#16641](https://github.com/elizaos/eliza/pull/16641)) is designed to fail closed unless explicitly enabled, but once it lands and is turned on it will:
- Reject mobile credentials in websocket query strings
- Require header-only transport for mobile credentials
- Introduce additional credential lifecycle semantics (ACK activation, revocation paths)

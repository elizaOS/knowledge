# ElizaOS Developer Update (2026-08-09 → 2026-08-15)

This week focused on making ElizaOS feel “production-shaped”: faster shared-agent cold starts, stronger trust boundaries at API edges (auth, A2A, public pages), and better end-user onboarding flows on `eliza.app` / `app.elizacloud.ai`. ## 1) Core Framework

### Runtime prompt + planner contracts hardened (turn completion, safety, and “no junk in chat”)
Several core/runtime changes tightened the “planner → tool → evaluator → delivery” loop so clients see fewer duplicate or meta-narration replies, and internal scaffolding doesn’t leak into user-visible output:

- **Turn scope is now mandatory on planner tool calls** to prevent premature completion and half-delivered work:  
  - PR: **#18247** “require the turn-scope declaration on every planner tool call”  
    https://github.com/elizaos/eliza/pull/18247
- **Planner loop resilience improvements** ensure preserved tool results can still be delivered when downstream synthesis fails:  
  - PR: **#18222**, **#18466**, **#18180**  
- **External-content envelope non-echo guarantee**: internal security wrappers are now stripped before any user-facing fallback path can echo them:  
  - PR: **#17629** “never echo the external-content security envelope into chat”  
    https://github.com/elizaos/eliza/pull/17629

### Provider execution now cancellation-safe (prevents poisoned caches/timeouts)
Provider deadlines were made abort/cancellation-safe so timeouts don’t cache “empty context” and degrade future turns.

- PR: **#17490** “make provider deadlines cancellation-safe”  
  https://github.com/elizaos/eliza/pull/17490

### Shared-agent cold-start latency reduced via cache prewarming
Shared agents now prewarm the exact Durable Object / shared-runtime caches at agent create time, substantially reducing first-message stalls.

- PR: **#18762** “prewarm shared-runtime turn caches at agent create”  
  https://github.com/elizaos/eliza/pull/18762
- Follow-up: **#18824** surfaced prewarm history failures instead of silently swallowing them  
  https://github.com/elizaos/eliza/pull/18824

### CI/runtime operational correctness improvements that directly affect dev velocity
- **Supervisor test fails fast when child never spawns** (reduces 30s timeout to immediate actionable failure)  
  - PR: **#18534**  
    https://github.com/elizaos/eliza/pull/18534

### Shared SSE contract canonicalized end-to-end

## 7) Breaking Changes / V1 → V2 Migration Warnings

### Cloud backup/snapshot behavior is being tightened (V1 safety alignment)
If you run legacy V1 snapshot/restore tooling or rely on large snapshot retention behavior, note the direction: budgets are now explicitly bounded by what restore can consume.

- PR: **#17180** “bound the v1 snapshot retain budget by what restore can consume”  
  https://github.com/elizaos/eliza/pull/17180

**Migration guidance:**
- Treat snapshot retention and restore as a coupled contract. If you previously retained large/long histories “just in case,” expect enforcement to reject/trim beyond restore’s bounded capacity.
- Validate your restore paths on staging with realistic data sizes before rolling forward production.

### A2A callers must not send `system` messages
As noted above, **#17643** rejects caller-authored `system` messages at the A2A boundary. If you have custom A2A clients that previously used `system` for routing/policy, migrate to:
- `user` messages plus explicit structured fields, or
- agent configuration / server-side policy injection.

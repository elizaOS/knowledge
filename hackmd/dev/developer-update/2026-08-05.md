## 1) Core Framework

### Provider execution is now cancellation-safe (prevents “timeout poison”)
A critical runtime safety fix landed earlier in the month but is directly relevant to this week’s integration work: provider deadlines are now **cancellation-safe** and no longer cache empty/partial context on deadline races ([#17490](https://github.com/elizaos/eliza/pull/17490)).

**What was happening**
- Providers were raced against a short implicit deadline.
- Losing work was not aborted, so it could continue consuming resources.
- Worse: a timeout could be cached as “no context,” creating repeatably degraded reasoning on subsequent turns.

**What changed**
- Provider work is now abortable and deadline enforcement won’t persist an “empty context” artifact as if it were valid provider output.
- Additional tests were added around provider budget composition and inference timing.

**Impact for plugin authors**
If your plugin registers state providers, prefer APIs that accept an `AbortSignal` (or propagate signals from runtime) and treat “no output due to cancellation” as distinct from “valid empty output”.

---

### Agent boot/benchmarking is now owner-controlled and shutdown-safe
Boot/benchmark and runtime maintenance received reliability improvements so the runtime owns shutdown and avoids orphan work, particularly under time-bounded paths ([#17531](https://github.com/elizaos/eliza/pull/17531)).

**Why it matters**
- Prevents dangling tasks during boot/benchmark flows.
- Reduces intermittent failures in CI and staged environments where boot timing is variable.

### Repo-wide “Shaw refactor” landed (large cleanup / re-org)
A very large refactor/cleanup was merged ([#17695](https://github.com/elizaos/eliza/pull/17695)). This appears to be a broad repository reshaping (mass deletions) intended to remove legacy/inert surfaces and align the monorepo with the current product direction.

### i18n catalog correctness is now enforced in CI (feature-quality gate)
The i18n system got a major correctness upgrade: `en.json` was restored as the true source catalog, dead keys purged, and the catalog checker was wired into CI ([#17606](https://github.com/elizaos/eliza/pull/17606)).

**Why this matters**
Previously, English renders could silently fall back to `defaultValue`, masking missing catalog keys and preventing real translation coverage.

**New contract**
- Missing source keys and orphan translations are errors.
- Translation lag is surfaced as warnings (optionally strict).

**Run locally**
```bash
node packages/scripts/check-i18n.mjs
```

## 3) Bug Fixes (critical fixes with technical context)

### Discord: readiness gating to prevent early ingress
Discord connector now waits for identity readiness before processing ingress, preventing `messageCreate` handling while `onReady` is still hydrating aliases and identity state ([#17645](https://github.com/elizaos/eliza/pull/17645)).

**Symptom**
- Early messages could be mis-attributed or processed before the connector had stable identity metadata, causing routing/permission confusion.

**Fix**
- Explicit readiness barrier and tests around connector loop + DM dispatch + service-account pool behavior.

---

### Stage-1 time correctness: CURRENT_TIME always renders
A correctness fix ensures Stage-1 prompt assembly always renders `CURRENT_TIME` and removes a brittle prose-regex “intent gate” that could prevent time refresh, producing wrong dates ([#17500](https://github.com/elizaos/eliza/pull/17500)).

**Impact**
- Agents answering time/date questions no longer risk stale timestamps due to misclassified intent.

---

### Tool failure honesty: stop falling into generic planner apology
Tool failures now propagate accurate failure context rather than collapsing into a generic fallback (“runtime step failed…”) ([#17501](https://github.com/elizaos/eliza/pull/17501)).

**Why you care**
- If you author tools/actions, error surfaces are now more explicit—test your tool error cases; users should see truthful, targeted failure messages.

---

### Test determinism: isolate agent memory + voice harness state
Two deterministic test fixes landed ([#17513](https://github.com/elizaos/eliza/pull/17513), closes [#17510](https://github.com/elizaos/eliza/issues/17510)):
- Memory remember-idempotency now runs through Vitest APIs (not Bun test APIs).
- Voice latency route suite resets module registry after tests to prevent mock leakage.

## 6) Model Provider Updates (OpenAI/Anthropic/DeepSeek/etc.)

### Prompt cache reuse improvements (Cerebras)
Prompt assembly was tuned to maximize prefix cache reuse by moving volatile fields (like `CURRENT_TIME`) to avoid invalidating large cached prompt prefixes ([#17515](https://github.com/elizaos/eliza/pull/17515)).

**Practical impact**
- Lower latency and cost on providers that cache fixed-size prefix blocks (notably Cerebras).

### Contribution tooling explicitly tracks model provenance
The eliza.army contribution workflow formalizes provider/model disclosure and attaches trajectories/evidence for live-model runs ([#17424](https://github.com/elizaos/eliza/pull/17424)). This isn’t a provider integration change per se, but it materially changes how model usage is recorded and audited in PR flows.

## 7) Breaking Changes (V1 → V2 migration warnings)

### Evidence Gate / Contribution Policy is now enforceable and stricter (breaking for contributor workflows)
If you are migrating automation or internal contributor tooling from earlier V1-era workflows, treat the eliza.army gates as **breaking changes**:

- UI-touching diffs require screenshots, MP4 walkthrough, and OCR artifacts.
- Evidence must be attachable via trusted GitHub artifact paths (and will fail closed if missing).
- Model provenance must be declared in standardized blocks.

Primary reference: ([#17424](https://github.com/elizaos/eliza/pull/17424)), plus ongoing evidence-gate robustness fixes like trusted fork text upload paths ([#17601](https://github.com/elizaos/eliza/pull/17601)).

### Cloud snapshot retention is now bounded by restore capacity (migration safety)
Cloud v1 snapshot retention was bounded to what restore can consume, explicitly as a v1 safety alignment step ([#17180](https://github.com/elizaos/eliza/pull/17180), scoped to “Immediate v1 safety alignment”). If you depend on legacy snapshot volume behavior, verify restore workflows before assuming older retention semantics.

### Known CI breaking edge (pending): Calendar typecheck ordering
An open CI issue notes nondeterministic TypeScript failures when Calendar typecheck runs before Video emits `.d.ts` artifacts ([#17721](https://github.com/elizaos/eliza/issues/17721)). Until fixed, maintainers may see flaky CI in clean runners; plugin developers should avoid introducing new cross-package type dependencies without explicit Turbo ordering edges.

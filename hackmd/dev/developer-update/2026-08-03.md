# ElizaOS Developer Update (Week of 2026-07-27 to 2026-08-02)

This week emphasized **runtime correctness under failure/cancellation**, **CI signal quality for contributors**, and the launch of **eliza.army** as a first-class contribution workflow.

## 1) Core Framework

### Cancellation-safe provider execution (core inference/runtime)
Provider composition and time budgeting were hardened to ensure that **deadlines don’t silently corrupt context** and that **timed-out providers are actually aborted** rather than continuing side effects in the background.

- **Fix:** provider deadlines are now cancellation-safe; timeouts no longer cache “empty context” and abort propagation is enforced.  
  PR: **#17490** “fix(core): make provider deadlines cancellation-safe”  
  https://github.com/elizaos/eliza/pull/17490

**Why it matters:** If you implement custom providers, you can no longer assume “timeout == provider didn’t run.” Providers must be prepared to stop work when aborted, or they may waste tokens/compute and still lose their output.

Example pattern (plugin/provider authors should follow the same contract):

```ts
export async function myProvider(ctx: ProviderContext) {
  const { signal } = ctx; // AbortSignal provided by runtime budget/deadline layer

  // Ensure downstream calls receive the signal
  const resp = await fetch(ctx.endpoint, { signal });

  // Avoid caching partial/empty state on abort
  if (signal.aborted) throw new Error("aborted");
  return resp.json();
}
```

### Owner-controlled boot/benchmark lifecycle (agent runtime)
Agent boot and benchmarking were adjusted so long-running or slow operations are **owner-controlled** rather than governed by hardcoded wall-clock races. This improves shutdown correctness and avoids “zombie” work continuing after a user cancels.

- **Fix:** benchmark/boot paths now respect cancellation signals and finalize runtime shutdown/leases cleanly.  
  PR: **#17531** “fix(agent): make benchmark and boot work owner-controlled”  
  https://github.com/elizaos/eliza/pull/17531

---

### Runtime contract clarity: connector discovery failures now surface as structured errors
When transport/connector discovery is unavailable, the runtime no longer falls back to a dashboard-default that can misrepresent transport ownership.

- **Fix:** surfaces a structured `ElizaError` instead of “no signal.”  
  PR: **#17580**  
  https://github.com/elizaos/eliza/pull/17580

## 3) Bug Fixes (Critical)

### Incorrect CURRENT_TIME rendering fixed (core messaging)
A production scenario showed the agent returning a date/time that was **~11 days wrong** due to an intent gate blocking the system’s time rendering behavior. This was removed so Stage-1 reliably renders current time.

- **Fix:** “Stage-1 always renders CURRENT_TIME — delete the prose-regex intent gate”  
  PR: **#17500**  
  https://github.com/elizaos/eliza/pull/17500

**Technical context:** if your workflows depend on consistent time grounding, this reduces nondeterminism caused by “intent classification” blocking system-provided time tokens.

---

### Tool failures now answer honestly instead of generic fallback (agent + app-control)
Multiple incidents were traced to failed tool calls feeding a generic planner apology rather than a correct “best-effort” response.

- **Fix:** “tool failures answer honestly instead of feeding the generic fallback”  
  PR: **#17501**  
  https://github.com/elizaos/eliza/pull/17501

**Developer note:** if you author tools/actions, ensure failures return actionable error semantics; the runtime now prefers truthful, localized handling over generic planner fallback.

---

### Self-hosted runner pruning could delete GitHub control directories (CI reliability)
A pruning script treated all children under `_work` as disposable, risking deletion of GitHub runner control directories (`_temp`, `_actions`, `_tool`, `_update`, `_PipelineMapping`) mid-run.

- **Fix:** protect runner control directories + regression coverage  
  PR: **#17535** (closes **#17534**)  
  https://github.com/elizaos/eliza/pull/17535  
  https://github.com/elizaos/eliza/issues/17534

Related: pruning now also avoids deleting runners whose state cannot be determined.

- **Fix:** “stop pruning runners whose state cannot be determined”  
  PR: **#17575**  
  https://github.com/elizaos/eliza/pull/17575

---

### Develop PR gate now runs plugin unit tests for changed plugins (pre-merge signal)
A real regression landed because plugin unit tests only ran post-merge. The develop PR gate now detects changed plugin packages and runs their unit tests pre-merge.

- **Fix/Test infra:** PR **#17552** (closes **#17550**)  
  https://github.com/elizaos/eliza/pull/17552  
  https://github.com/elizaos/eliza/issues/17550

## 4) API Changes

### Cloud snapshot retention budget bounded by restore consumption (safety alignment)
Cloud v1 snapshot retention now respects what restore can actually consume, preventing runaway retain behavior and improving safety under restore constraints.

- **Bugfix (behavioral change):** PR **#17180**  
  https://github.com/elizaos/eliza/pull/17180

### Typed lifecycle reads in Cloud services (Date correctness)
Lifecycle reads were typed so date fields are real `Date` objects (rather than raw strings from DB rows), preventing subtle time-comparison and lock/retry bugs.

- **Bugfix:** PR **#17262**  
  https://github.com/elizaos/eliza/pull/17262

**Migration guidance:** these are intended to be additive/safe, but if you have external tooling reading lifecycle fields, re-check assumptions about string timestamps vs `Date`.

### PR policy/evidence + attribution gates are now effectively part of the developer workflow
With **#17424**, contribution policy is more enforceable via templates and CI checks. If you contribute via PRs, expect failures if you omit required evidence/attribution rows.

- PR: **#17424**  
  https://github.com/elizaos/eliza/pull/17424

### CI behavior on fork PRs may still produce confusing red checks (known issue)
Fork PR workflows can be held at `action_required` until a maintainer approves runs, but aggregate gates can time out waiting for checks that will never start.

- Issue: **#17551** (OPEN)  
  https://github.com/elizaos/eliza/issues/17551

**Workaround (maintainers):** approve fork workflow runs early to avoid gate timeouts and wasted runner minutes.
